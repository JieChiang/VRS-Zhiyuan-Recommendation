# Qt 桌面版

桌面版复用现有 FastAPI 和 Web 页面，使用 PyQt6 / Qt WebEngine 显示，不需要另外维护一套界面。

## 启动

安装 `requirements.txt` 后，在项目环境中运行：

```powershell
python desktop_app.py
# 使用其他端口
python desktop_app.py --port 8000
```

Windows 也可以双击根目录的 `启动桌面版.bat`。脚本里的 `VRS_PYTHON` 指向本机 Conda 环境，换电脑后先修改这个路径。

默认端口是 8765。桌面入口会检查该端口：已有 VRS 服务就复用，没有则新建后端；被其他程序占用时会提示更换端口，不会停止其他进程。

关闭最后一个桌面窗口时，会停止本次新建的后端。复用的服务继续运行。

## 日常使用

- 登录与浏览器版相同，目前仍是演示登录，任意非空用户名和密码即可进入。
- F5 或工具栏“刷新”可重新加载页面。
- 内部新窗口共享登录和草稿。外部 HTTP/HTTPS 链接在系统浏览器打开。
- 点击“导出 Excel”后选择保存位置；下载结果显示在底部状态栏。取消保存不会产生下载文件。
- 工具栏“在浏览器中打开”可以打开当前页面，但普通浏览器需要使用自己的登录状态。

## 数据保存在哪里

桌面数据放在 `storage/desktop/`：

| 目录 | 用途 |
| --- | --- |
| `profile/` | 页面 localStorage、草稿等浏览器状态 |
| `cache/` | 页面缓存 |
| `downloads/` | 默认下载位置，可在保存对话框中更改 |
| `tmp/` | 临时文件 |

这些目录不提交到 Git。桌面与 Chrome、Edge 等浏览器的 localStorage 独立，不会自动迁移草稿；后端 SQLite 仍使用项目的同一份数据。登录 Cookie 不跨桌面会话保存。

## 常见问题

**提示端口被占用**：确认占用端口的服务是不是 VRS，或使用 `--port` 换一个端口。

**页面能打开，但推荐查询失败**：在侧栏检查“环境与 API 配置”。Qt 只负责显示页面，Neo4j 仍需要单独启动并导入图谱。

**提示缺少桌面依赖**：确认使用的是项目虚拟环境，在该环境中重新安装 `requirements.txt`。

**修改 Qt 启动代码后出现原生退出**：不要使用 `QApplication([])`。WebEngine 要求至少传入一个有效的程序名，当前入口统一使用 `QApplication(['VRS-desktop'])`。见 [Qt 构造函数说明](https://doc.qt.io/qt-6/qapplication.html#QApplication)。

## 测试

```powershell
python -m unittest discover -s tests -v
python scripts/verify_desktop.py
python scripts/verify_desktop.py --entry
```

Qt 测试使用隐藏窗口，检查登录、推荐页、Excel 下载和取消保存、刷新后的状态保留、内部弹窗、外链交接，以及后端复用和退出。保存对话框的选择由测试函数代替，下载仍走 Qt 的实际下载信号。

截图和样本位于 `storage/desktop-verification/`。测试不会调用真实 AI 或写入图谱。
